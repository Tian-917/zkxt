## P1.5 已知限制：Seata 全局事务实际没生效

| 项 | 现状 | 结论 |
|---|---|---|
| 分布式事务 | 全项目只有 1 处 `@GlobalTransactional`，写在 `CourseDraftServiceImpl.copySubject2Draft()` 上——而它**只被同类内部的 `downShelf()` 调用**，Spring AOP 拦截不到自调用，注解等于没写 | 实测验证：把注解上移到 `downShelf()` 后，日志里确实出现 `GlobalTransactionalInterceptor`、全局事务真的开启了 |
| 但开启后下架必失败 | 下架的 copy 逻辑用的是 `INSERT INTO course_draft (...) SELECT ... FROM course`，Seata AT **不支持 `INSERT ... SELECT`**，直接抛 `NotSupportYetException: not support the sql syntax insert with query` | 已回退为本地事务，并在代码注释里写明原因 |
| 要真正启用需要 | 把这个 mapper 的三条 `INSERT ... SELECT` 改成「先 select 再批量 insert」，让 Seata 能解析 SQL 生成 undo log | 工作量约 2 小时，收益低（当前下架是单库操作），暂不做 |

> 这也是为什么很多项目"引入了 Seata 但实际没跑全局事务"——语法限制比配置更容易被忽略。
