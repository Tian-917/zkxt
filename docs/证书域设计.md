# 证书域（zk-cert）设计说明

> 这是本次包装改造里**唯一新增的业务域**，也是"职考云"区别于普通卖课平台的地方：
> 别人的终点是"学完"，这里的终点是"拿证"。

## 1. 业务闭环

```
学习(学时累计) ──┐
                 ├─► 资格判定 ──► 签发证书 ──► 验真 ──► 到期复证提醒
正式考(成绩)  ──┘      │              │
                    不达标拒绝     失败落 cert_task ──► XXL-Job 补偿重放
```

**真实链路（已打通）**：

```
exam-service.submitExam()
  └─ score >= 60 且 type == 正式考
       ├─ LearningClient.queryStudyMinutes(courseId)   → learning-service 汇总已学小节时长
       └─ RabbitMQ  cert.topic / cert.issue  {CertIssueDTO}
              └─ cert-service 消费：校验收学时(≥120分钟)+成绩(≥60) → 发证（幂等）
```

- 事件载荷 `CertIssueDTO` 放在 **zk-api**（`com.zhikao.api.dto.cert`），exam 与 cert 共用
- 交换机 / routingKey 统一定义在 **zk-common 的 `MqConstants`**
- 学时接口：`GET /learning-records/course/{courseId}/study-minutes`（学习服务按「已完成小节的视频时长」求和，秒 → 分钟）

## 2. 表结构

**certificate（证书）**

| 字段 | 说明 |
|---|---|
| cert_no | 证书编号 `ZK-YYYY-NNNNNN`，**唯一索引** |
| user_id + exam_id | **联合唯一索引** —— 一人一场考试只能发一张证，这是幂等的根 |
| score / cert_type | 考核成绩、证书类型 |
| issue_time / expire_time | 签发时间、有效期至（5 年） |
| verify_code | 12 位验真码，**唯一索引**，对外只用它 |
| notified | 是否已做到期提醒 |

**cert_task（补偿任务 / 本地消息表）**

失败的发证请求落一条，`uk(biz_type, biz_id)` 去重，XXL-Job 定期重放，最多 3 次。

## 3. 三个关键设计（面试就讲这三个）

### 3.1 发证幂等：唯一索引兜底，不是靠 if

```java
// 先查（快路径）
Certificate exists = getByUserAndExam(userId, examId);
if (exists != null) return toVO(exists);

// 并发下两边都查不到 -> 都 insert -> 唯一索引让一个失败
try { insert(cert); }
catch (DuplicateKeyException e) {
    Certificate dup = getByUserAndExam(userId, examId);
    if (dup != null) return toVO(dup);   // 幂等返回
    // 否则是编号冲突，换号重试
}
```

**为什么不能只用"先查后插"**：查和插之间有窗口，500 并发同时到达时全都能查到"不存在"。唯一索引是数据库层的互斥，才是真正的保证。

### 3.2 编号唯一：Redis 号段 + 唯一索引双保险

```java
Long seq = redis.opsForValue().increment("zk:cert:seq:" + year);  // 1,2,3...
String certNo = String.format("ZK-%d-%06d", year, seq);
```

- Redis 负责**高并发下不重复**（INCR 是原子的）
- DB 唯一索引负责**Redis 挂掉/回档后不重复**（序号可能回退，插入冲突就换号重试，最多 3 次）
- 为什么不用 UUID：证书要给人看、要能口述、要能按年归档
- 为什么不用数据库自增：多库/多实例下不连续、会暴露发证量

### 3.3 最终一致：失败落表 + 定时补偿

```java
try { issue(dto); }                                  // 正常
catch (BadRequestException e) { /* 资格不达标，不重试 */ }
catch (Exception e) { saveTask(dto); }               // Redis/DB 抖动才落表
```

区分**业务拒绝**（重试无意义）和**系统异常**（可重试），是补偿表不变成垃圾堆的关键。

## 4. 接口清单

| 方法 | 路径（网关前缀 `/cts`） | 说明 | 鉴权 |
|---|---|---|---|
| POST | `/cert/issue` | 同步发证（内部/管理端） | 需要 |
| POST | `/cert/exam-passed` | 模拟考试服务发"考核通过"事件（走 MQ 异步发证） | 需要 |
| GET | `/cert/my` | 我的证书列表 | 需要 |
| GET | `/cert/{certNo}` | 证书详情（仅本人） | 需要 |
| GET | `/cert/verify/{verifyCode}` | **公开验真**（脱敏，只返回"林*"） | **免登录** |

## 5. 自测记录（2026-10 实测）

| 用例 | 预期 | 实际 |
|---|---|---|
| 首次发证 | 返回编号 | `ZK-2026-000001`，有效期 2031-10-19，剩余 1825 天 |
| 同一 examId 再发 | 返回同一张 | 编号一致 `ZK-2026-000001` |
| 成绩 50 分 | 拒绝 | 400「考核成绩未达到 60 分，不予签发」 |
| 学时 30 分钟 | 拒绝 | 400「累计学时未达到 120 分钟，不予签发」 |
| 验真（正确码） | 有效 | `valid:true`，持证人脱敏 `林*` |
| 验真（错误码） | 无效 | `valid:false` |
| MQ 异步发证 | 自动签发 | 监听线程消费后生成 `ZK-2026-000002`，requestId 透传 |
| 用户隔离 | 看不到别人 | user=2 查 user=1 的证书 → 「无权查看他人证书」 |
| 网关验真 | 免登录 | `GET /cts/cert/verify/xxx` → 200 |
| 网关我的证书 | 匿名 | 返回空列表（不泄露数据） |
| **端到端（2026-10 实测）** | 正式考全对 → 自动发证 | `ZK-2026-000005`，持证人「林晓」，90 分，验真 `valid=true` |
