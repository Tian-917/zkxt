# 错题本设计（zk-exam 子域）

> 定位：把「练」这一环补上，让"学 → 练 → 考 → 证"四段闭环成型。
> 挂在考试域而不是新开服务：交卷判分已经在里面，错题归档是判分的下游动作，拆出去只会多一次 RPC。

## 1. 数据模型

```sql
wrong_question(
  user_id, question_id,        -- uk(user_id, question_id)：一题一条
  course_id, section_id, section_name,  -- 小节当作"考点"
  last_answer,                 -- 最近一次作答（复盘用）
  wrong_count,                 -- 累计答错次数（不是行数）
  last_wrong_time,
  mastered                     -- 0 未掌握 / 1 已掌握
)
```

**为什么一题一条而不是一次一条**：错题本的价值是"这道题我错了 N 次"，按次存会变成流水账，聚合和去重都难做。

## 2. 两个关键动作

### 2.1 交卷归档（幂等累加）

```sql
INSERT INTO wrong_question (...) VALUES (...)
ON DUPLICATE KEY UPDATE
  wrong_count = wrong_count + 1,
  last_wrong_time = NOW(),
  last_answer = VALUES(last_answer),
  mastered = 0;          -- 又错了就重新变成"未掌握"
```

用唯一索引 + `ON DUPLICATE KEY UPDATE`，并发交卷也不会插出两行。

### 2.2 重练答对 → 自动掌握

```sql
UPDATE wrong_question SET mastered = 1
WHERE user_id = ? AND question_id = ?;
```

交卷时逐题处理：错的 upsert，对的 `markMastered`（没有记录时影响 0 行，无副作用）。
效果是**错题本自己会变短**——这比"手动点已掌握"更符合真实学习行为。

## 3. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/wrong/list?mastered=0` | 我的错题（带题干、选项、我的答案、正确答案、解析） |
| GET | `/wrong/points` | 按考点聚合：每个考点多少错题、累计错几次 |
| POST | `/wrong/{questionId}/mastered` | 手动标记已掌握 |
| DELETE | `/wrong/{questionId}` | 移出错题本 |

## 4. 实测（2026-11-19）

| 场景 | 结果 |
|---|---|
| 18 题练习卷全选 A | 答对 2/18，错题本新增 16 条 |
| 按考点聚合 | `1.1 会计概述 · 考点精讲` 16 道 / 累计 32 次 |
| 再刷教资小节（6 题全错） | 聚合出现第 2 组：`1.1 职业理念 · 考点精讲` 6 道 / 6 次 |
| 同考点重练全对 | 未掌握 0，已掌握 17（自动掌握生效） |
| 同一题错两次 | `wrong_count` 累加到 2，仍只有 1 行 |

## 5. 已知取舍

- **考点粒度 = 小节**：题上没有独立的知识点标签，用"考试所属小节"当考点。要做真正的知识点图谱，得给 `question` 加 `point_id` 并建知识点表。
- **逐题 upsert 是 N 次 SQL**：18 题就是 18 次。题量大时应该改成批量 `INSERT ... ON DUPLICATE KEY UPDATE`（一条 SQL 多组 VALUES），这是一个可以主动说出来的优化点。
- 错题本只统计"本人"，没有做班级/全局错题率排行（那是另一个功能）。
